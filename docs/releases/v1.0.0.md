# APIWatch v1.0.0

First public release of APIWatch, a self-hosted API monitoring dashboard built with Python,
FastAPI and SQLite. It checks HTTP endpoints on a schedule and records uptime and response
times. It also opens incidents for repeated failures and flags changes in JSON responses.

APIWatch is a single-user tool for local use. It has no authentication, so do not expose
it to untrusted networks.

## Highlights

- **Health checks.** Asynchronous `GET`/`HEAD` checks classified as UP, DEGRADED (slower
  than your threshold) or DOWN, with typed error categories and sanitized messages.
- **Scheduling.** APScheduler-based, with jobs rebuilt from SQLite on startup and no
  overlapping checks of the same monitor.
- **Analytics.** Uptime, average, minimum and maximum response time, and last successful
  check, computed from stored checks for the last 24 hours, the last 7 days or all data.
  N/A is shown when there is no data.
- **Incidents.** Opened after 2 consecutive DOWN checks and resolved automatically on
  recovery.
- **JSON change detection.** Added, removed and type-changed top-level fields, with an
  explicit approval step before the baseline changes.
- **Dashboard.** Dark, responsive and self-contained: summary cards, monitor table,
  response-time charts, incidents, failed checks and per-monitor details.
- **Offline demo.** A deterministic mock API and a seed script; no API keys or external
  services needed.

## Security

- Monitor targets must resolve to public IP addresses. Loopback is allowed only with the
  development-only `APIWATCH_ALLOW_LOCALHOST` switch. Private, link-local/metadata, CGNAT
  and IPv6 transition ranges are always rejected.
- Targets are re-validated before every check, and the connection goes to the validated
  address, which closes the DNS-rebinding window between the check and the connection.
- Redirects are not followed, response reads are size-limited, and timeouts cover the
  whole check.
- The local server rejects unknown `Host` headers and cross-origin browser writes, and
  binds to `127.0.0.1` by default.

These measures reduce SSRF risk. They do not remove it entirely: for example, a public
host that relays requests into a private network cannot be detected. See the
"Security and deployment limitations" section of the README and `SECURITY.md`.

## Requirements and installation

- Python 3.12 or 3.13 (tested in CI) and [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/berkdogutan/ApiWatch.git
cd ApiWatch
uv sync
uv run apiwatch            # http://127.0.0.1:8000
```

The README describes the offline demo (`demo.mock_api` and `demo.seed`).

## Known limitations

- Run a single Uvicorn worker. Multiple workers or replicas duplicate scheduled checks.
- No authentication, notifications, history retention or schema migrations.
- Only `GET`/`HEAD` without custom headers. JSON comparison covers top-level fields only.
